# Следующее обучение по сохранённым наблюдениям

Для новой версии добавлена команда train-reviewed.ps1. Она читает ручную разметку из местной базы и использует её в обучении. Если сохранённых пригодных наблюдений нет, обучение останавливается: старая разметка не выдаётся за новую.

## 1. Проверить, что записи действительно сохранены

Откройте http://127.0.0.1:8000/review на этом компьютере. Введите FORTE_API_KEY из .env и нажмите «Открыть разметку».

Для каждой из шести записей:

1. Выберите файл слева.
2. Заполните «Наблюдаемое действие» своими словами — только то, что различимо в видео.
3. Укажите начало и конец действия. Конец должен быть позже начала и находиться в пределах записи.
4. Выберите рабочую категорию; для положительной записи она обязательна.
5. Выберите видимость «Действие различимо» и статус «Просмотрено», если действительно уверены в наблюдении. Не отмечайте плохо видимый эпизод как различимый ради запуска обучения.
6. Нажмите «Сохранить наблюдение» и дождитесь сообщения о сохранении.

После этого обновите страницу, снова откройте разметку и выберите тот же файл. Заполненные поля должны восстановиться. Переход на другую запись или просмотр ролика сам по себе ничего не сохраняет.

«Черновик», «Нужно уточнить», частично закрытые действия и записи без границ не поступают в это обучение. Они сохраняются для дальнейшего разбора. Если шесть записей находятся в другом файле, сначала нужно указать путь к этому файлу и проверить его формат.

Описания остаются в местном интерфейсе. По условиям кейса банковские видео, кадры и их описания не отправляются в облачные AI.

## 2. Что изменится в обучении

Ранее положительным примером был небольшой фрагмент около одной отметки из Excel. Теперь подтверждённые границы вашего действия заменяют отметку соответствующего файла. Если у точного повтора есть другая, ещё не разобранная отметка, она сохраняется отдельно.

В пределах подтверждённого действия выбираются обучающие окна. Если действие короче шага выборки кадров, используется ближайшее временное окно, контекст которого охватывает середину действия. Сами записанные границы не изменяются. При шаге кадров примерно две секунды короткое действие может быть плохо различимо — новая разметка не устраняет это ограничение автоматически.

Подтверждённые окна получают вдвое больший относительный вес. Это относится и к обычным действиям на отрицательных видео: они помогают отличать похожую нормальную операцию от положительного примера. Общий вес каждого видео и баланс классов сохраняются, чтобы длинные записи не заглушали остальные.

На этом шаге используются границы действий и визуальные признаки. Текст описания проверяется на наличие и сохраняется для аудита, но не превращается в признаки классификатора. Рабочие категории пока также не обучают отдельный детектор типов нарушения. Большая Qwen не переобучается; обучается лёгкий визуальный классификатор.

## 3. Как сохраняется сравнимость

Новая версия берёт исходное разделение baseline-v1: 24 уникальных видео для обучения, 8 для выбора настроек и 8 для проверки. Видео не перемешиваются заново.

Ручные наблюдения из validation или test не используются при обучении. В отчёте указывается, какие записи приняты, а какие исключены и почему. Точные повторы остаются в одной группе.

Проверочная восьмёрка уже использовалась в предыдущем эксперименте. Сравнение с ней будет повторной диагностикой, а не новой независимой оценкой. По одному такому сравнению нельзя объявлять готовность банковского детектора.

## 4. Запустить обучение

После сохранения разметки откройте папку проекта в VS Code, затем «Терминал» → «Создать терминал». Введите:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\train-reviewed.ps1

Новая версия сохраняется в models/trained/reviewed-v2. Старый baseline-v1 остаётся отдельным экспериментом.

Нужны уже установленные тренировочные зависимости. При их отсутствии:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-training.ps1

Из существующего кэша берутся числовые признаки видео. Интернет для обучения после установки не требуется.

## 5. Какие результаты появятся

| Файл | Что в нём |
| --- | --- |
| candidate.npz | Обученные числовые веса новой версии. |
| report.json | Ошибки новой версии и сравнение с baseline-v1. |
| annotation-audit.json | Число принятых наблюдений и причины исключений. |
| annotations-private.json | Зафиксированная местная копия принятых наблюдений. |
| protocol.json | Условия эксперимента и отпечаток снимка разметки. |

Если после запуска изменить сохранённую разметку, повторный запуск под тем же именем остановится: данные уже относятся к другому эксперименту. Для следующего обоснованного опыта задаётся новое имя, например:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\train-reviewed.ps1 -RunName reviewed-v3

Сайт автоматически не переключается на экспериментальную версию. Сначала нужно оценить пропуски, ложные срабатывания и найденные моменты, учитывая небольшую проверочную выборку.

## 6. Сообщения, которые помогут найти проблему

| Причина в аудите | Простое объяснение |
| --- | --- |
| not_reviewed | Запись ещё не имеет статуса «Просмотрено». |
| not_clear | Видимость отмечена как частичная или неясная. |
| missing_observation | Не заполнено описание действия. |
| invalid_interval | Нет одной из границ, они перепутаны или выходят за длительность. |
| unknown_positive_category | Для положительной записи нет существующей рабочей категории. |
| held_out_video | Запись относится к проверочной части и не поступает в обучение. |

Разметка, веса и подробные результаты хранятся локально и исключены из Git. В репозиторий сохраняются только код, тесты и инструкция.
