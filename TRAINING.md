# Как устроено первое обучение Clearity

Обучение уже выполнено на этом компьютере. Файлы весов и отчёт лежат локально в models/trained/baseline-v1. Это экспериментальная версия; она не включается на сайте автоматически.

## Шаг 1. Понять, что мы обучаем

Большая Qwen продолжает описывать кадры и не переобучалась. Для первого опыта добавлен отдельный небольшой классификатор: он получает числовые признаки нескольких соседних кадров и учится отличать фрагменты с меткой нарушения от фрагментов без такой метки.

Готовая ResNet18 извлекает визуальные признаки. Её веса заморожены. Мы обучили нормализацию признаков и веса логистической регрессии. Это настоящее обучение небольшого компонента на ваших примерах, но не дообучение всей Qwen и не обучение нейросети с нуля.

Кадр рассматривается в двух видах: центральная область и уменьшенный полный кадр. Изображения не загружаются в облачные AI. Из соседних кадров строятся признаки внешнего вида и изменения во времени. Шаг выборки — примерно 2 секунды; точное время берётся из декодера. Быстрые движения всё равно могут быть пропущены.

Официальная модель ResNet18 и описание обработки изображений: https://github.com/onnx/models/blob/main/validated/vision/classification/resnet/README.md

## Шаг 2. Разделить данные до обучения

42 файла содержат 40 уникальных видео. Два точных повтора объединены по SHA256 — отпечатку содержимого файла. Повторы не могут оказаться одновременно в обучении и в итоговом тесте.

| Часть | Уникальных видео | Зачем нужна |
| --- | ---: | --- |
| Обучение | 24 | По этим видео меняются веса классификатора. |
| Проверка настроек — validation | 8 | Выбираются сила регуляризации и порог срабатывания. |
| Итоговый тест — test | 8 | Один раз измеряется результат после выбора настроек. |

Разделение фиксировано заранее, seed=17. Порядок файлов на диске его не меняет. В каждом наборе есть оба класса. Нельзя перебирать разбиения, пока не получится красивый процент.

Точный повтор — только один вид сходства. Разделение пока не гарантирует независимость людей, камер и съёмочных сессий. При подготовке следующего набора это нужно проверить отдельно.

Почему обучение и итоговая проверка разделены: https://scikit-learn.org/stable/modules/cross_validation.html

## Шаг 3. Использовать имеющуюся разметку аккуратно

В исходном Excel есть бинарная метка и отметка времени, но нет полного описания события и всех его границ. Это слабая разметка.

Для положительных примеров берутся окна с центром не дальше примерно одной секунды от указанной отметки. Контекст окна — соседние выбранные кадры. Остальная часть положительного видео не становится отрицательным примером автоматически: там тоже могут быть события.

Отрицательные окна берутся из видео с меткой «без нарушения». Вес примеров распределяется по видео и классам, чтобы длинная отрицательная запись не заглушала остальные примеры.

У одинаковых положительных файлов с разными отметками обе отметки сохраняются как слабые положительные примеры. Человек должен проверить, относятся ли они к разным действиям или в таблице есть неточность.

## Шаг 4. Обучить и выбрать настройки

Нормализация обучается только на обучающих окнах. Значения validation и test не участвуют в вычислении её среднего и масштаба.

На validation выбираются параметр C из заранее заданного небольшого списка и порог срабатывания. C управляет тем, насколько сильно модель может подстраиваться под отдельные примеры. Порог — граница числовой оценки, после которой появляется положительный сигнал. Эта оценка не является измеренной вероятностью нарушения.

Для целого видео используется максимальная оценка среди окон. У длинных записей больше окон и, следовательно, больше возможностей для ложного срабатывания. Это ограничение первого подхода нужно учитывать при дальнейшей проверке.

После выбора настроек веса сохраняются в candidate.npz. Файл содержит только числовые массивы; загрузка не использует pickle. Настройки и протокол записаны рядом. Веса Qwen остаются прежними.

## Шаг 5. Прочитать результат без самообмана

Смотрите не только на процент правильных ответов:

- Пропуск — видео с меткой нарушения, на котором модель не дала положительный сигнал.
- Ложное срабатывание — положительный сигнал на видео с меткой «без нарушения».
- Precision — какая доля срабатываний соответствует положительным меткам.
- Recall — какую долю видео с положительной меткой удалось найти.

Всего восемь тестовых видео — очень небольшая проверка. Один ответ меняет точность на 12,5 процентного пункта. Даже высокий процент на таком наборе не доказывает надёжность на новых съёмках.

Отдельно проверяется, находится ли самый высокий пик рядом с исходной отметкой. Правильно угадать метку всего видео и правильно найти момент действия — разные задачи. Бинарный классификатор также не объясняет тип нарушения и его нормативное основание.

Сравнение с Qwen, если оно выполнено, находится в qwen-comparison.json. Для этого сравнения положительный сигнал Qwen означает наличие хотя бы одного possible_concern. Отсутствие такого сигнала не превращается в юридический вердикт «нарушений нет». Если модель не закончила обработку, результат отмечается как ошибка, а не как отрицательный ответ.

Тест нельзя использовать для подбора порога после просмотра его ошибок. После многократного использования этих же восьми видео потребуется новый независимый набор для окончательной оценки.

## Шаг 6. Что делать для следующего улучшения

Откройте местный интерфейс: http://127.0.0.1:8000/review. На публичной ссылке исходной разметки нет.

1. Вставьте FORTE_API_KEY из .env и нажмите «Открыть разметку».
2. Выберите запись из обучающей части. Первые шесть записей для разбора перечислены в отдельном местном отчёте по эксперименту.
3. Нажмите «Открыть видео», затем «За 3 секунды до отметки». При необходимости выберите скорость ×0,5.
4. В поле «Наблюдаемое действие» опишите, что действительно видно: кто перемещает какой предмет, откуда и куда. Не приписывайте намерения и не называйте неразличимый предмет деньгами.
5. Отметьте начало и конец действия кнопками «Взять время плеера».
6. Выберите рабочую категорию. Если неясно, оставьте её пустой, выберите «Нужно уточнить» и запишите причину.
7. Нажмите «Сохранить наблюдение».
8. Так же разберите похожие обычные действия на отрицательных видео. Они нужны, чтобы модель перестала считать любую передачу предмета подозрительной.

Заполняйте описания в местном интерфейсе. Банковские видео, кадры и их описания по условиям кейса должны оставаться вне облачных AI. В чат достаточно сообщить количество сохранённых наблюдений, например «готовы шесть записей».

Текущий скрипт baseline-v1 обучается по исходной бинарной разметке. Новые ручные наблюдения не подхватываются им автоматически. Для следующего эксперимента потребуется подготовить и проверить новый набор событий по сохранённым аннотациям. Просто повторный запуск прежней команды не улучшит модель.

## Шаг 7. Как повторить технический запуск

На этом компьютере всё уже установлено. На другом компьютере откройте папку проекта в VS Code: «Файл» → «Открыть папку». Затем «Терминал» → «Создать терминал» и выполните:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-training.ps1

Устанавливаются scikit-learn с зависимостями и небольшой визуальный компонент ONNX, около 47 МБ. Скрипт проверяет контрольную сумму. После этого само обучение работает без интернета.

Чтобы запустить первый эксперимент:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\train.ps1

Если отчёт baseline-v1 уже существует, команда сохраняет зафиксированный результат и не запускает подбор заново. При незавершённом запуске используются ранее подготовленные признаки. Если исходные данные или протокол изменились, команда остановится, чтобы не смешать результаты разных экспериментов.

Для нового эксперимента имя задаётся явно, например:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\train.ps1 -RunName baseline-v2

Само по себе новое имя не делает тест снова неизвестным и не является способом улучшения. Перед новым экспериментом нужны обоснованные изменения данных или метода и план независимой проверки.

После установки тренировочных зависимостей проверки кода запускаются так:

    .\.venv\Scripts\python.exe -m pytest -q

## Какие файлы добавлены

| Файл | Что делает |
| --- | --- |
| app/features.py | Локально читает кадры и превращает их в числовые признаки. |
| app/training.py | Разделяет повторы, обучает классификатор, выбирает порог и считает ошибки. |
| app/train_run.py | Фиксирует протокол, проверяет видео, сохраняет кэш и запускает эксперимент. |
| setup-training.ps1 | Устанавливает зависимости и скачивает визуальные веса. |
| train.ps1 | Запускает обучение из терминала. |

Данные, признаки, обученные веса и подробные результаты исключены из Git. В репозиторий попадает код, тесты и эта инструкция.
