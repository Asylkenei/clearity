# Clearity: первый запуск локальной модели — простыми словами

На этом компьютере модель уже скачана и подключена. Начните с шага 1. Команды установки нужны только на другом компьютере или после удаления файлов модели.

## 1. Попробовать сейчас

1. Откройте http://127.0.0.1:8000/ на этом компьютере. Обновите страницу клавишами Ctrl+F5.
2. Под надписью «Что сделать с видео» выберите «Поиск возможных проблем · локальная модель».
3. Дождитесь надписи «Модель подключена».
4. В поле «Ключ доступа» вставьте значение FORTE_API_KEY из местного файла .env. Это символы после знака =, без имени настройки. Для публичной ссылки используется другой ключ — FORTE_PUBLIC_API_KEY.
5. Нажмите «Выберите видео» и выберите небольшой файл .mov. Для первого опыта лучше запись до 20 секунд. Модель принимает видео до 3 минут, файл до 100 МБ.
6. Нажмите «Запустить просмотр». Дождитесь результата; не закрывайте вкладку. Сервер показывает число обработанных частей. Работа может занять несколько минут.
7. Сравните текст модели с кадрами. При необходимости включите «Показать только возможные проблемы».

Если вы открываете сайт с телефона, используйте действующую публичную HTTPS-ссылку. Адрес 127.0.0.1 на телефоне означает сам телефон и не ведёт на ваш компьютер.

## 2. Что именно подключено

Qwen3-VL-2B-Instruct — небольшая модель, которая получает изображения и отвечает текстом. Это уже обученная модель общего назначения: мы пока не обучали её на банковских примерах.

llama.cpp — программа, которая запускает модель на процессоре вашего компьютера. На этом компьютере используется CPU Ryzen 5 и 16 ГБ памяти. Модель загружается один раз, после чего местный и публичный сайты обращаются к одному экземпляру по адресу 127.0.0.1:8081.

Скачаны два файла: основной Q4_K_M (около 1,11 ГБ) и визуальный компонент Q8_0 (около 0,45 ГБ). Визуальный компонент переводит изображения в представление, понятное модели. Размер файлов уменьшен с помощью квантования — хранения чисел с меньшей точностью. Контрольные суммы проверены при установке.

Официальная модель и лицензия Apache 2.0: https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct-GGUF

Движок: https://github.com/ggml-org/llama.cpp/releases/tag/b11714

## 3. Как понимать результат

«Возможная проблема» — модель заметила действие, которое предлагает проверить человеку. Это гипотеза, а не установленное нарушение.

«Наблюдение модели» — описание видимого действия без отдельного сигнала о возможной проблеме. Обычный пересчёт или передача наличных сами по себе не считаются нарушением.

«Не удалось уверенно рассмотреть» — предметы, руки или действие плохо видны. Откройте исходную запись и посмотрите вручную.

«Возможных проблем: 0» не означает «нарушений нет». Модель могла ошибиться, плохо рассмотреть предмет или пропустить момент между кадрами.

Время под картинкой берётся из декодера исходного видео. Это время выбранного кадра, а не точно установленное начало действия. Модель не придумывает номера секунд: сервер связывает её ответ с реальными кадрами.

Сейчас из каждой 20-секундной части берутся три кадра: начало, середина и ближе к концу. Для каждой части модель выбирает до одного наиболее заметного действия. Например, в записи 0–20 секунд рассматриваются кадры около 0, 10 и 18 секунд. Действие на 4-й секунде может быть пропущено. Выбор сделан для первого запуска на обычном процессоре; это обзор, а не непрерывное наблюдение за каждым движением.

Нормативные правила ещё не подтверждены, подробная разметка не заполнена, точность не измерена. Поэтому официальный endpoint /api/v1/analyze пока отвечает 503 VIOLATION_DETECTOR_NOT_VALIDATED. Работающий экспериментальный просмотр доступен через /api/v1/inspect. Он не подменяет обязательный вердикт задания и пока не завершает решение кейса.

## 4. Как запустить снова после перезагрузки

Откройте папку проекта в VS Code: «Файл» → «Открыть папку» → выберите outputs/forte-vision. Откройте «Терминал» → «Создать терминал». Терминал — нижняя панель, куда вводятся команды. Вводите одну команду и нажимайте Enter.

В первом терминале запустите модель:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\start-model.ps1

Дождитесь строк model loaded и listening. При первом запуске это занимает время. Оставьте терминал открытым.

Откройте второй терминал кнопкой «+» в панели терминалов. Для местного сайта выполните:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1

Откройте в браузере http://127.0.0.1:8000/. Если эти программы уже запущены, второй раз запускать их не нужно. При сообщении о занятом порте проверьте существующие терминалы.

Чтобы работала публичная ссылка, в отдельном терминале запустите:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\start-public.ps1

Ещё в одном терминале запустите туннель:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\start-tunnel.ps1

Скопируйте HTTPS-адрес из вывода туннеля. При новом запуске он меняется. Для публичного сайта нужен FORTE_PUBLIC_API_KEY. Компьютер и эти терминалы должны продолжать работать. Местный сервер start.ps1 нужен дополнительно, если хотите разбирать исходную разметку через /review.

## 5. Установка модели на другом компьютере

Сначала установите зависимости самого проекта командой setup.ps1 по основному README. Затем в терминале папки проекта выполните:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-model.ps1

Понадобится интернет для скачивания примерно 1,6 ГБ. Скрипт сохранит файлы в models и .tools, проверит SHA256 и не загрузит ваши видео куда-либо.

Откройте .env и добавьте отдельной строкой, если её ещё нет:

    FORTE_MODEL_ENABLED=1

Сохраните файл сочетанием Ctrl+S. Перезапустите сервер сайта, если он был запущен до изменения настройки. Затем выполните команды из шага 4. После установки модель запускается с параметром --offline и обращается только к местным файлам.

## 6. Как связаны файлы и код

Писать код заново не требуется — он уже добавлен.

| Файл | Простое объяснение |
| --- | --- |
| app/model_setup.py | Скачивает фиксированные версии файлов и проверяет, не повреждены ли они. |
| start-model.ps1 | Загружает модель в память и оставляет её ждать местных запросов. |
| app/inspection.py | Выбирает кадры, отправляет их только на 127.0.0.1, проверяет ответ и связывает наблюдения со временем. |
| app/main.py | Принимает новое видео, создаёт задание и возвращает результат сайту. |
| static/app.js | Показывает ход обработки, текст модели и кадры. |

Схема работы: браузер → ваш сервер сайта → OpenCV выбирает кадры → местная Qwen → проверка формата ответа → результат в браузере.

Интерфейс запросов совместим с распространённым Chat Completions API, но используется местный llama.cpp, без вызова облачных AI API. В коде адрес модели зафиксирован на loopback; прокси из окружения и HTTP-переадресации отключены.

## 7. Если что-то не получилось

| Сообщение | Что делать |
| --- | --- |
| Модель выключена или загружается | Откройте терминал модели и дождитесь загрузки. Если он закрыт — запустите start-model.ps1. Обновите страницу. |
| Неверный ключ | Для 8000 используйте FORTE_API_KEY, для публичной ссылки — FORTE_PUBLIC_API_KEY. |
| Модель уже обрабатывает видео | Дождитесь предыдущего задания и повторите загрузку. |
| Не закончила ответ / некорректный результат | Это ошибка анализа, а не отсутствие нарушений. Попробуйте короткий фрагмент и проверьте окно модели. |
| Истекло время обработки | За 4 минуты модель не закончила просмотр. Выберите более короткий фрагмент. |
| Сайт с телефона не открывается | Проверьте, включён ли компьютер и работают ли публичный сервер и туннель. После нового запуска туннеля возьмите новую ссылку. |

Загруженный для задания MOV удаляется после обработки; выбранные кадры и ответы сохраняются локально в runtime. При публичной загрузке результат передаётся обратно через HTTPS-туннель. Исходный датасет и ручная разметка через публичный сайт недоступны. Файлы модели, .env, видео и runtime исключены из Git.

## 8. Следующий практический этап

На местном сайте откройте /review. Разберите несколько роликов с нарушениями и несколько без них: запишите видимое действие простыми словами, отметьте начало и конец, выберите рабочую категорию. Не считайте исходную бинарную метку готовым объяснением действия.

После этого можно уточнить критерии, подтвердить применимые нормативные пункты и сравнить предсказания с отдельной проверочной выборкой. Одинаковые видео должны попадать в одну группу, иначе оценка точности будет завышена. Только после измерения пропусков и ложных срабатываний можно переходить к нормативному вердикту API.
